## Thumbnail status

- **2 cached** — YouTube, via its public oEmbed endpoint (no credentials needed)
- **37 pending** — every Instagram link

Instagram is not a bug and not an oversight. Its endpoints block
unauthenticated requests: `/embed/captioned/` returns a ~620KB JavaScript
shell with no post data, and `?__a=1` returns 404. Its CDN URLs are also
signed and expire within days, so a scraped thumbnail would break on its own.
Rather than invent a caption or hotlink a URL that dies, those tiles render a
designed placeholder carrying the brand and shortcode, with a working link.

Two independent fallbacks guarantee the page never shows a broken image:

1. the `status` gate — anything not `available` renders the placeholder;
2. an `onerror` handler — a cached thumb that 404s degrades to the same tile.

### To fill them

Save each cover as `assets/thumbs/ig-<shortcode>.jpg`, then run:

```sh
node scripts/fetch-meta.mjs --rescan
```

That flips the record's status to `available`. With a Meta app token in
`IG_ACCESS_TOKEN`, the official oEmbed endpoint supplies title and thumbnail
automatically — but engagement counts stay unavailable, because Instagram
only ever exposes those for posts the token's own account owns.
